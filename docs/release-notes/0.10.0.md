# HikeJournal 0.10.0 · Edibility by plant part

Release scope is Android and API. Android build 206. GitHub tag `v0.10.0`.

## Android

- The Field Guide shows named plant parts with visible Edible, Toxic, Conditional food use, and Caution labels. Hazards lead the section, and each finding links directly to its source.
- Plant maturity, growing region, preparation requirements, and contact hazards are shown when the evidence specifies them. Checklist-only records and genus-level identifications explain why there is no part-level answer.
- Entries with more than one exact identification show available references under their scientific names. The Field Guide food-use filter recognizes those exact references. The photo indicator remains opt-in.
- Android `versionName` and the shared API version advance from **0.9.0** to **0.10.0**. Android `versionCode` advances from **205** to **206**.

## API

- Added 53 findings from 35 sources across 39 verified species. Examples include Black Highbush Blueberry berries, elderberry leaves and flowers, air potato bulbils and tubers, and the different maturity stages of bitter melon.
- The API preserves the existing checklist assessments and supports independently sourced findings when a checklist match is absent. The dataset version includes the new catalog revision for cache invalidation.
- The account-scoped Field Guide audit found 417 visible plant entries. Of these, 38 have part-level findings, 100 have checklist-only evidence, 273 have no exact reference, and six are above the species rank.
- This release uses the existing production database schema and feature flag. WCFP still requires periodic taxonomic revalidation.

## Verification

- Python passed 588 tests. Android passed 192 Debug and 192 Release unit tests and nine Android 15 tests for the edibility experience. Release lint reported zero errors, 60 warnings, and one hint.
- All 39 catalog taxa resolved to unique active iNaturalist IDs with the expected name and rank. The merged reference was checked against production guide records.
- `./build_android.command personal` produced a signed APK and AAB. The APK verifier reported no findings, and strict AAB verification confirmed the permanent signer.
- APK signatures verified on API 26–27 and 28–36. The signing lineage and capabilities matched build 205. An in-place Android 15 upgrade preserved the app ID and initial installation time, and the updated app launched and resumed.

## Debug-log triage

The signed upgrade recorded no launch crash. The verification and test runners reported the existing API 26–27 newer signature-scheme warning, Starlette dependency deprecation, Android location API deprecation, and test locale deprecation.
