# HikeJournal 0.8.40 tracking parity release

## Release scope

Android + iOS. The shared semantic version remains 0.8.40; this platform
release advances Android `versionCode` from 164 to 165 and iOS
`CURRENT_PROJECT_VERSION` from 16 to 17. API/shared services and Web have no
functional changes and no artifacts are shipped for them.

## Android

- Pause from the tracking screen now requires an explicit confirmation.
- The foreground notification Pause action opens the same confirmation instead
  of pausing immediately; stale pre-release pause actions no longer bypass it.
- Voice announcements now say “Hike paused” and “Hike resumed”.
- Whole-mile announcements now include total distance, total active time, and
  the elapsed active time for the last completed mile.
- Android version metadata: `versionName` 0.8.40, `versionCode` 165.

## iOS

- Pause from the tracking screen and Live Activity deep link now require the
  same explicit confirmation.
- Voice announcements now say “Hike paused” and “Hike resumed” when enabled.
- Whole-mile announcements now use the same total-distance, total-time, and
  last-mile-time wording as Android.
- iOS version metadata: marketing version 0.8.40, build 17.

## API/shared services

- No functional changes.

## Web

- No functional changes.

## Diagnosis and debug-log triage

- No production log bundle or physical-device reproduction was available.
  The change targets the one-tap pause paths and announcement state handling
  directly.

## Validation

- Android `:app:testDebugUnitTest`: passed.
- iOS `HikeJournalTracking` package tests: 29 passed.
- `./build_android.command personal`: passed with versionCode 165, release
  verifier success, strict AAB signature verification, expected permanent
  signer identity, and canonical APK/AAB promotion.
- Full iOS simulator build compiled the changed tracking and UI sources, then
  failed in Xcode simulator packaging validation because XCTest support
  frameworks were copied without Info.plist files; this is an environment/toolchain
  packaging failure, not a Swift compile or test failure.

No iOS archive is attached to this GitHub release; the iOS parity source and
build-number change are included for the next signed App Store submission.
