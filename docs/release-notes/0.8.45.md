# HikeJournal 0.8.45 — Android and API egress reduction

## Release scope

Android and API. Canonical `VERSION` advances to `0.8.45`; Android
`versionName` is `0.8.45` and `versionCode` advances from `175` to `176`.

## Android

- Reuse a recently loaded hike detail for 30 seconds when reopening it, while
  preserving photo and route paging, explicit refreshes, and forced reloads
  after sync and edits.
- Reuse recently validated species index and detail responses for up to one
  minute. Pull-to-refresh and local species changes invalidate this cache.
- Keep existing photo presentation and GPS-safe phone-original media selection
  unchanged.

## API and Supabase

- Replace library-wide photo and observation transfers with database-side
  hike and standalone-journal summaries containing only counts and the selected
  cover image metadata.
- Honor Android's `include_photos=false` request for Everyday sightings, and
  serve its photos in bounded pages with an explicit mobile projection.
- Avoid recounting hike-linked observations in a second unlinked-observation
  query; narrow Android photo-observation and observation-history projections.
- Use a species-page-specific observation projection that omits fields needed
  only by review and publishing flows.
- Install the owner-scoped summary and standalone-photo paging functions in the
  production Supabase project. The SQL migration notifies PostgREST to reload
  its schema cache.

## Egress investigation

The Supabase dashboard showed 6.392 GB of uncached egress against a 5 GB plan
quota. Available request logs did not retain enough history to attribute the
644 MB day to a specific endpoint. Code inspection found that Android's
Everyday sightings header request ignored `include_photos=false` and loaded the
full standalone photo and observation collections before Android requested the
same photos in pages. The hike archive also enumerated photo rows to compute
counts and covers. Species screens used a broader observation projection than
they display. These paths are now bounded or return only the fields needed by
the screen. The release does not change displayed hike, photo, or species
content, and does not downscale user media.

verification. Final artifact hashes and the API deployment check are recorded
