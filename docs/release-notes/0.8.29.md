# HikeJournal 0.8.29

## iOS

- The existing recorded-route capture and upload path remains compatible.
- Routes saved by the iPhone recorder can now be surfaced by the web map even
  when the spatial index is unavailable during migration or recovery.

## Android

- No functional Android changes were made.
- Version metadata advanced to `versionName` 0.8.29 and `versionCode` 150.

## Web

- Fixed the map route-count fallback that converted a missing or unreadable
  `track_geom` spatial column into zero saved routes.
- Saved route imports now continue through the compatibility GeoJSON renderer,
  preventing the false “no recorded route” message for an outing such as
  `walk`.

## API

- No endpoint or schema change is required.
- The existing `/v1/hikes/{hike_id}/route` upload contract continues to store
  the parsed route in `track_geojson`; the web map now handles that stored route
  safely before spatial indexing is available.

## Verification

- Route parser, API route-upload, repository, and map regression tests passed.
- iOS Debug build succeeded; route finalization/upload coverage passed, and the
  isolated timing-sensitive recorder test passed on rerun. The full suite still
  intermittently fails that unrelated concurrency test under simulator load.
- Android personal APK/AAB built and passed release verification for 0.8.29.
