# HikeJournal 0.8.31

## iOS

- Field Quest creation now uses the location from the initial Discover search.
  Current-location searches save their coordinates directly; searches for a
  saved place keep their place association. Choosing another area is no longer
  an extra required step.
- “What might I see today?” now has resilient species imagery in the briefing
  header, species list, and detail view, including legacy photo payloads and
  collection images when available.
- Species detail sheets now include `Map sightings` so the selected species can
  be opened in the existing sightings map flow.
- Place profiles load their core profile independently from slow river/weather
  conditions, and place route lookups are scoped to the selected place to
  reduce slow loads and false “Place profile unavailable” results.

## Android

- No functional Android changes were made in this release.
- Version metadata advanced to `versionName` 0.8.31 and `versionCode` 152.

## Web

- No web behavior changed in this release.

## API

- Field Quest creation now accepts either a saved `area_id` or the latitude,
  longitude, and display name from the originating Discover search. Coordinate
  quests store their search context without requiring a saved place.
- Field briefing photo data now preserves nested reference photos and supplies
  a compatible fallback when only a flat photo URL is available.
- Place profile route-import queries are scoped to the hikes belonging to the
  requested place instead of loading every route import.
