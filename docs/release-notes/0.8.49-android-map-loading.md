# HikeJournal Android 0.8.49 — Map loading fix

## Release scope and versions

Android only. Canonical `VERSION` and Android `versionName` remain `0.8.49`;
Android `versionCode` advances from `184` to `185`. Release tag:
`android-v0.8.49-map-loading`.

## Android

Opening Map now applies the summary bounds even when the routes and photo
lists have not changed. The resulting camera movement requests photos for the
visible area. Finishing the summary request without bounds also updates the
native map so it can fit cached routes.

The earlier viewport-loading and camera-focus changes were still present.
They contained a timing-dependent Compose/native-view integration bug:
`initialBounds` and `waitForInitialBounds` were assigned to a remembered
controller outside `AndroidView.update`. Those assignments did not invalidate
the native view's update lambda. If the summary arrived after the map style
loaded and the route/photo lists stayed equal (as with an unchanged route
cache), Compose could skip that update. The camera never focused, and the
initial camera-idle callback needed to request viewport photos never occurred.
Toggling an empty photo layer could not start the missing camera update.

Capture and assign both summary inputs inside `AndroidView.update`, ensuring
bounds-only and loading-only changes reach MapLibre. Keep the existing bounded
photo requests, clustering, route cache, and GPS-safe original-media browser.

Add Android emulator regression tests that exercise the real MapLibre view:
late summary arrival with unchanged empty route/photo lists, actual photo
rendering and visibility toggles, subsequent camera requests, loading completion
with cached routes, and summary bounds replacing an earlier cached route fit.
The late-summary test failed against the previous code and passed after the fix.
