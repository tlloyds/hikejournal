# HikeJournal 0.8.32

## Release scope

Android + API. The Android client and mobile API share the canonical release
version, so the API version metadata advances with this Android release. iOS
and Web are included in this note for parity and explicitly have no functional
changes.

## Android

- Fixed authenticated refresh handling so a temporary network, timeout, or
  retryable server response does not clear a valid Google session. Android now
  clears the stored session only after an explicit authentication rejection.
- Fixed the offline-cache fallback policy. HTTP authentication and other
  client errors no longer turn a stale `species-review.json` into an
  “OFFLINE COPY” queue. Last-known review data remains available for genuine
  connectivity and retryable server failures only.
- Fixed stale account state after session expiry. If the refresh token is
  rejected, the app now moves to the Google sign-in gate while preserving local
  hikes, photos, and queued changes instead of continuing to display the old
  account as signed in.
- After a successful sign-in, only pending operations paused for the expired
  session are requeued. Unrelated sync attention items remain untouched for
  deliberate review.
- Review and Publish now track their own data freshness. A cached Publish load
  cannot pause Species Review, and concurrent screen refreshes no longer race
  through one global offline flag.
- Kept the GPS-safe phone-original photo browser
  (`LocalMediaPickerDialog`/`LocalMediaLibrary`) wired into the journal.
  No system/cloud-only picker or photo/video permission change was made.
- Android version metadata: `versionName` 0.8.32, `versionCode` 153.

## iOS

- No functional changes. The existing iOS API actor already preserves sessions
  across transport failures, coalesces refreshes, and signs the visible app
  state out when authentication is actually rejected; the Android contradiction
  was not present in the reviewed iOS path.
- `ios/Config/Version.xcconfig` was synchronized to canonical version 0.8.32
  for cross-platform validation. `CURRENT_PROJECT_VERSION` remains 10; no iOS
  archive, build-number increment, or App Store submission was made.

## API

- No API endpoint, schema, or runtime behavior changed.
- The mobile API continues to derive its health and compatibility version from
  `VERSION`; this release therefore reports 0.8.32 after the main-branch
  deployment trigger publishes the revision.

## Web

- No functional Web or Streamlit changes.

## Shared/repository guidance

## Diagnosis and debug-log triage

The screenshots are consistent with one failure chain: Android previously
treated a 401 from an authenticated queue request as a cacheable network error,
while a refresh exception cleared the stored session. The in-memory view model
still held the old account, so the UI could show a logged-in Settings account
and simultaneously accumulate “Sign in with Google to continue” sync
attention. A concurrent Review/Publish refresh could also overwrite the shared
offline flag.

No production log bundle or physical Android device was attached. Static code
triage identified the chain above; the release emulator launch produced no
`FATAL EXCEPTION` or `AndroidRuntime` entries after the upgrade smoke test.
