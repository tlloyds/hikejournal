# HikeJournal 0.8.33

## Release scope

Android + API version metadata. This release ships the Android journal route
preview. The API has no endpoint or runtime behavior changes, but its reported
compatibility version advances with the canonical `VERSION`. iOS and Web have
no functional changes and no platform artifacts are shipped for them.

## Android

- Added the iOS-style Route section to the Android journal detail view, directly
  after field notes and before weather and media content.
- Added a 230 dp route preview that uses the existing satellite snapshot style,
  route line, and start/end markers so saved GPS tracks are visible in the
  journal without opening the full map.
- Added an offline-safe route sketch fallback. If satellite tiles are unavailable
  or MapLibre cannot initialize, the journal still shows the saved route instead
  of a blank or crashing surface.
- Added accessibility text describing the recorded route and its saved GPS point
  and segment counts.
- Kept the GPS-safe phone-original browser
  (`LocalMediaPickerDialog`/`LocalMediaLibrary`) wired into the journal. No
  system/cloud-only picker or photo/video permission change was made.
- Android version metadata: `versionName` 0.8.33, `versionCode` 154.

## iOS

- No functional changes. The existing iOS route preview remains unchanged.
- `ios/Config/Version.xcconfig` was synchronized to canonical version 0.8.33
  for cross-platform version validation. `CURRENT_PROJECT_VERSION` remains 10;
  no iOS archive, build-number increment, or App Store submission was made.

## API

- No API endpoint, schema, or runtime behavior changed.
- The mobile API continues to derive its health and compatibility version from
  `VERSION`; the main-branch deployment trigger should publish the 0.8.33
  metadata with this release.

## Web

- No functional Web or Streamlit changes.

## Diagnosis and debug-log triage

- The Android route preview now treats map imagery as an enhancement rather than
  a prerequisite. A connectivity or MapLibre snapshot failure is contained and
  falls back to a locally rendered route line.
- No new production log bundle or physical-device log was available for this
  feature. The Android debug build and unit tests completed without compiler,
  lint, or test failures.
