# HikeJournal Android 0.8.44 — iNaturalist connection during sync

## Release scope

Android only. This release makes iNaturalist connection independent of the
field-note sync connectivity indicator and improves progress and error feedback
in Settings. Canonical `VERSION` and Android `versionName` remain `0.8.44`;
Android `versionCode` advances from `174` to `175`.

## Android

- Start the iNaturalist OAuth URL request even while queued field notes are
  syncing or the field-sync monitor temporarily reports no validated network.
  The OAuth request now determines whether its service is reachable instead of
  being blocked by the separate field-sync state.
- Show a spinner and “Connecting…” label while the request is in progress and
  disable repeated taps until it completes.
- Show connection failures next to the iNaturalist button in Settings, where
  the message remains visible above the open dialog. Other connect entry
  points continue to use the app-wide error banner.
- Android metadata: `versionName` `0.8.44`, `versionCode` `175`.

## How the failure happened

The iNaturalist button was guarded by the field-sync connectivity state. The
August 31 Android authentication and sync-stability change (`1f3b659`) switched
that guard to `syncStatus.connected`; a September 28 connectivity recovery
change (`75d78ff`) made that status require Android's validated-internet
capability. When this status was temporarily false, `connectInat()` returned
before requesting an OAuth URL, even though starting the separate OAuth request
was the right way to discover whether the service could be reached. The queued
sync indicator exposed the same temporary connectivity state.

The failure message was sent to the app-wide error banner at the bottom of the
main screen. Settings is a modal dialog drawn above that banner, so the error
was partly hidden and the button had no progress state. This made the tap look
like a no-op until the banner appeared below the dialog. The screenshots match
that code path. There was no device log bundle to confirm the precise network
transition on the phone. Relaunching recreated the connectivity monitor and
could clear the temporary state, which explains why retrying after reopening
worked.

## Debug-log triage

No physical-device log bundle was supplied, and no new Android debug logging
was added. The Android 15 emulator started the upgraded app without an
`AndroidRuntime` fatal exception. It had no signed-in account or configured
companion endpoint, so the live iNaturalist OAuth exchange could not be run
end-to-end there.
