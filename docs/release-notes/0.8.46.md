# HikeJournal 0.8.46 — Android map coverage and bounded map egress

## Release scope

Android and API. Canonical `VERSION` advances to `0.8.46`; Android
`versionName` is `0.8.46` and `versionCode` advances from `178` to `179`.

## Android

- Load the total geotagged-photo count and map extent separately from visible
  photo details.
- Request photo markers for the current camera bounds after map movement,
  with a short debounce and cancellation of stale requests.
- Show clusters at overview zooms and when a viewport is dense. Selecting a
  cluster zooms into its area; individual photo markers appear as the map
  resolves the cluster. Route visibility and the photo visibility control are
  preserved.

## API and Supabase

- Add owner-scoped `/v1/map/summary` and `/v1/map/viewport` routes. The summary
  returns a count and bounds; viewport responses include only the current
  bounds and use database-side clustering, capped at 2,500 rendered features.
- Add PostGIS-backed RPCs for visible hike photos and standalone journal
  photos. Ownership is resolved directly against all hikes in SQL, avoiding a
  second PostgREST row-cap limit on a large hike history. The SQL migration is
  additive and has a companion rollback script.
- Remove the main map's dependency on the capped `/v1/sightings` snapshot.
- Advertise `viewport_map_photos` in the authenticated `/v1/config` capability
  list so clients and operators can confirm API support.

## iOS, Web, and shared behavior

- iOS: no functional changes. Marketing version metadata follows the canonical
  version; iOS build number remains unchanged and no iOS artifact was built.
- Web: no functional changes and no Web artifacts were built.
- Shared user-facing behavior: no functional changes outside the Android map.

## Egress investigation

The map previously read the complete sightings list once and retained that
snapshot while the camera moved. The mobile database function returned more
rows than the PostgREST default response cap, so the map showed only the first
100 photos; panning and zooming did not request a new region. The updated map
transfers a compact summary once and fetches at most the clustered or visible
features needed for each debounced viewport. This preserves a path to every
geotagged photo while avoiding a full photo-row transfer on each map open.

## Debug-log triage

No device log bundle was supplied. The Android 15 emulator accepted the
signed in-place update from version code 178 to 179 and launched the updated
app without a `FATAL EXCEPTION` in the captured log window.
